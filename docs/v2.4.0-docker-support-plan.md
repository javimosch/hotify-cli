# Hotify CLI v2.4.0 — Basic Docker Support Plan

## Overview
Add basic Docker container management to hotify-cli, integrated with Traefik's Docker provider for automatic service discovery and routing.

## Background

Current hotify-cli manages:
- Binary apps (via start/stop commands)
- Traefik configuration (file-based provider)
- DNS records (Cloudflare API)

Docker support would enable:
- Containerized apps to be managed alongside binary apps
- Automatic Traefik routing via Docker labels
- Consistent CLI interface for both binary and containerized apps

## Design Principles

1. **Follow existing patterns** — Docker commands should mirror the existing app process commands (start/stop/restart/status)
2. **Traefik Docker provider** — Use Traefik's built-in Docker provider for automatic container discovery
3. **Simple first** — Basic container management only; no compose orchestration yet
4. **Local-only initially** — Docker commands run on the local server (no remote Docker API yet)

## Features

### 1. Docker Container Management (docker_ops.go)

Add a new file for Docker operations:

```go
// dockerOps.go - Docker container management

type DockerContainer struct {
    ID      string
    Name    string
    Image   string
    Status  string
    Ports   []string
    Labels  map[string]string
}

// List all containers
func dockerList() ([]DockerContainer, error)

// Start a container
func dockerStart(containerID string) error

// Stop a container
func dockerStop(containerID string) error

// Restart a container
func dockerRestart(containerID string error

// Get container status
func dockerStatus(containerID string) (*DockerContainer, error)
```

Implementation via `docker` CLI commands (simpler than Docker SDK):

```bash
docker ps -a --format "{{.ID}}\t{{.Names}}\t{{.Image}}\t{{.Status}}\t{{.Ports}}"
docker start <id>
docker stop <id>
docker restart <id>
docker inspect <id>
```

### 2. Traefik Docker Provider Integration

Add Docker provider to Traefik main config:

```yaml
providers:
  docker:
    endpoint: "unix:///var/run/docker.sock"
    exposedByDefault: false  # security: only expose labeled containers
  file:
    filename: /etc/traefik/dynamic.yml
    watch: true
```

Container labels for Traefik routing:

```yaml
labels:
  - "traefik.enable=true"
  - "traefik.http.routers.myapp.rule=Host(\`myapp.example.com\`)"
  - "traefik.http.routers.myapp.entrypoints=websecure"
  - "traefik.http.routers.myapp.tls.certresolver=letsencrypt"
  - "traefik.http.services.myapp.loadbalancer.server.port=8080"
```

### 3. CLI Commands

Add new top-level commands:

```bash
# Docker container management
hotify-cli docker list              # List all containers
hotify-cli docker start <id>       # Start a container
hotify-cli docker stop <id>        # Stop a container
hotify-cli docker restart <id>     # Restart a container
hotify-cli docker status <id>      # Container status
hotify-cli docker logs <id>        # Container logs (optional)

# Enable Traefik Docker provider
hotify-cli docker enable-traefik   # Add Docker provider to traefik.yml
```

### 4. App Config Extension

Add `type` field to App struct to distinguish binary vs container apps:

```go
type App struct {
    ID         string `json:"id"`
    Name       string `json:"name"`
    Domain     string `json:"domain"`
    Port       int    `json:"port"`
    Command    string `json:"command"`  // for binary apps
    Image      string `json:"image"`    // for Docker apps
    Type       string `json:"type"`     // "binary" or "docker"
    Source     string `json:"source,omitempty"`
    Status     string `json:"status"`
    // ... existing fields
}
```

### 5. Docker-Specific Setup Command

Add `docker-setup` command to initialize a containerized app:

```bash
hotify-cli docker-setup \
  --id myapp \
  --name "My Docker App" \
  --domain myapp \
  --image nginx:latest \
  --port 8080
```

This would:
1. Add app to config with `type: docker`
2. Generate recommended Traefik labels
3. Optionally create a docker run command with labels
4. Setup DNS via existing setup-dns command

## Security Considerations

1. **Traefik Docker provider** — `exposedByDefault: false` for security
2. **Docker socket access** — hotify-cli runs as regular user, needs sudo for docker commands
3. **Label validation** — validate Traefik labels before applying
4. **Container isolation** — don't manage system containers (only user containers)

## Future Enhancements (v2.5+)

1. Docker Compose support
2. Remote Docker API (manage containers on remote hosts)

## Notes

- Docker commands will use `sudo docker` by default (most systems require sudo)
- Traefik Docker provider requires Docker socket access (`/var/run/docker.sock`)
- Container names are used as IDs for simplicity (user-friendly)
- Keep it simple: no container orchestration, just basic management
