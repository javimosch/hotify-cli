- Traefik has a configuration error on dk1 (unrelated to v2.1.0 changes)

### Critical Bug Discovered
**Daemon Process PID Tracking Issue:**
When `start` command executes `sh -c <command>`, it tracks the shell process PID. For daemon apps that fork (like cmdcenter), the shell exits immediately and the actual daemon runs as a child process with a different PID. This makes the tracked PID invalid for subsequent operations.

**Example:**
```
hotify-cli start --id cmdcenter --local
→ Tracks PID 909884 (shell process)
→ Shell exits, actual daemon is PID 909889
→ Tracked PID 909884 is now invalid
```

**Impact:**
- pause/resume/stop operations fail with invalid PID
- Requires manual PID correction to work around
- Affects any app that forks or daemonizes

### Testing Limitations

### Recommendations
- **Fix PID tracking for daemon processes** - Modify `handleLocalStart` to track child process PID instead of shell PID
- Options for fixing PID tracking:
  - Use `exec.Command` without `sh -c` wrapper for direct execution
  - Implement process group tracking to follow forked children
  - Add PID discovery via process name matching as fallback
  - Add `--no-fork` flag for apps that don't daemonize
- Add validation for PID existence before sending signals
- Consider adding a --force flag for stop to handle stuck processes
- Create proper test harness that doesn't rely on manual config manipulation
- Test with foreground apps to validate natural PID tracking after fix
